# ADR 3: Choosing K3d for Local Kubernetes

## Context
Phase 9 required deploying the application to a Kubernetes cluster locally to test Deployments, Services, and Horizontal Pod Autoscaling (HPA).

## Decision
We chose **k3d** (k3s in Docker) over minikube, kind, or Docker Desktop Kubernetes.

## Rationale
- Extremely lightweight and spins up in seconds.
- Uses existing Docker infrastructure.
- Comes with Traefik ingress controller pre-installed, simplifying Phase 9 requirements.
- Native command `k3d image import` makes it easy to test local images without setting up a local registry.

## Consequences
- Requires developers to learn k3d-specific port mapping commands (`-p 8080:80@loadbalancer`).
- Storage provisioning works differently than managed cloud providers.
